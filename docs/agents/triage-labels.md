# Змістовні мітки

У репозиторії не використовуються службові мітки стану на кшталт `needs-triage` або `ready-for-agent`. Мітки мають описувати, про що саме помилка або зміна.

## Принципи

- Додавати одну чи кілька вузьких міток за компонентом або природою проблеми.
- Повторно використовувати наявну мітку, якщо її значення відповідає проблемі.
- Перед створенням нової мітки перевіряти `gh label list`.
- Не додавати мітку лише для позначення того, хто або який інструмент працюватиме над issue.

## Початковий словник

| Мітка | Застосування |
| --- | --- |
| `telegram` | Telegram Bot API, MTProto, канали або сесії |
| `ingestion` | Отримання, нормалізація чи збереження вхідних повідомлень |
| `database` | PostgreSQL, міграції або запити |
| `api` | HTTP API, SSE або інтеграційні контракти |
| `docker` | Контейнери, Compose або runtime-конфігурація |
| `configuration` | Змінні середовища та зовнішнє налаштування |
| `security` | Секрети, доступ або захист даних |
| `frontend` | Вебінтерфейс і карта |

Словник можна розширювати змістовними мітками, коли з'являється новий клас проблем.
